# 资料库闭环 · 发布前手工验收

目标：验证「对话产出 → 存为笔记 → 下次自动召回 → 回答带引用 → 点击回源」在真实
Electron 里成立。约 5–8 分钟。

## 准备

1. 用 preview 构建启动应用（`bun run dev` 或打包后的 preview）。
2. 设置 → 通用 → 资料库：
   - 「资料库位置」可读、可打开；
   - 「自动召回」开关默认**开**。
3. 准备一个带 `docs/` 的项目目录，以及至少一条 `.md` 笔记。

## 检查项

### 1. 存为笔记

- 任选一条助手回答，`···` →「存为笔记」。
- 期望：toast「已存为笔记」，路径在 `项目/<项目目录名>/<标题>.md`；
  文件管理器里能看到该文件；frontmatter 含 `title / created / source_session`
  （来源会话存在时）。
- 点 toast 的「打开」→ 切到资料库页并选中该笔记。

### 2. 输入框建议

- 新建对话，输入与该笔记标题/标签相关的 2–4 个字。
- 期望：输入框上方出现「可能相关」+ 最多 3 条；点击一条插入 `:library` 芯片；
  点 × 后本次查询不再出现。

### 3. 发送保底 + agent 召回

- 输入一句自然语言（不点 @、不提文件名），发送。
- 期望：模型调 `kb_search`（或直接 `kb_read`）并给出带来源的回答；
  引用芯片可点击，打开的资料库笔记/项目文件正确。
- 项目文件引用应跳到 cite 里的行并居中；markdown 会自动切到源码态。

### 4. 刷新与展开态

- 资料库左树展开两层文件夹，点顶栏「刷新」。
- 期望：树不塌成「加载中」单行，文件夹保持展开；内容原地更新。
- 整窗刷新（Cmd/Ctrl+R）后：
  - 期望：同一资料库位置下，展开态和选中文件恢复；
  - 换资料库位置后：旧根的展开态不带到新根。

### 5. 附加根

- 项目设置里给项目加一个附加代码根，根下放 `docs/ext.md`。
- 在项目会话里问附加根文档里的内容。
- 期望：`kb_search project` 命中 `root=<附加根>`；`kb_read` 能按 root 读到；
  文档地图出现 `[label] docs/ext.md`。

### 6. 非 git 目录正文

- 附加根如果是非 git 目录，同样问其中某段正文的独有短语。
- 期望：能命中（不是只按文件名）；命中行号正确。

### 7. 使用记录

- 让 agent 读过某篇笔记后，打开该笔记。
- 期望：状态行出现「被 N 个任务引用」；悬浮显示最近任务标题。
- 删除该会话后重新打开笔记：计数应减少。

### 8. 开关回退

- 设置 → 通用 → 资料库：关闭「自动召回」。
- 新建对话输入相关词：不再出现建议条；发送内容里不再有 `library-hints`
  隐藏块（可在后端提示词/转录里核对）。
- 重新打开开关：恢复正常。已发出的旧消息不受影响。

## 通过标准

- 1–8 全部通过；
- 控制台无新增 error；
- 发送首条消息的额外延迟主观可接受（冷启动首条不明显卡顿）。
