# 模式总览：这个应用里有五个「模式」，别混

它们分属四个正交维度 + 一个无人值守专用维度。**同一个词在不同位置含义不同**，
所以先认维度，再认名字。

```
会话模式 (SessionMode)   agent / plan / ask / goal        能不能改、以什么形态干活
权限档位 (ApprovalLevel) 变更前确认 / 工作区内自动 /        改之前问不问
                        自动编辑 / 完全访问
工作模式 (AppMode)       编码 / 工作 / 设计                 面向谁、提示词什么风格
自动化权限档              只读 / 可写工作区 / 全放开          无人值守时怎么裁决
( AutomationToolPolicy)
```

前三个是**会话级**、可随时切、随会话存；第四个是**任务级**，只属于某条自动化任务。

## 一、会话模式（能不能改）

| | |
|---|---|
| 值 | `agent` / `plan` / `ask` / `goal` |
| 管什么 | 工具表、系统提示词的「模式段」、能不能写 |
| 在哪切 | `/ask` `/plan` `/goal` 指令；composer「+」菜单 → 模式 → **能力**组；切了之后底栏右侧的**能力胶囊**（点它退出） |
| 存哪 | `sessions.mode` 列（会话级）+ kv `pi.mode`（全局「最近一次使用」，给新会话兜底） |
| 模型可见 | **是**（模式段进系统提示词，模型知道自己在哪一档） |
| 生效 | 立即，含运行中（热换提示词与工具表） |

- `agent`：完整工具集
- `plan`：结构性只读，靠 `plan_write` 写计划、`plan_exit` 拿批准后回 agent 实施（模型也能自己 `plan_enter`）
- `ask`：纯只读子集（无 bash），需要动代码时用出口工具 `ask_needs_work` 提议切档
- `goal`：完整工具集 + 跨轮自治，详见 [goal-mode-design.md](./goal-mode-design.md)

## 二、权限档位（问不问）

| | |
|---|---|
| 值 | 变更前确认 `ask` / 工作区内自动 `workspace-write` / 自动编辑 `auto-edit` / 完全访问 `auto` |
| 管什么 | **逐工具审批**：改动前是否弹卡等你点 |
| 在哪切 | 底栏那个下拉（只列这四项）；composer「+」菜单 → 模式 → **权限**组；Shift+Tab 在四项间循环 |
| 存哪 | `sessions.approval_level` 列 + kv `pi.mode`（同上） |
| 模型可见 | **否**——它不进系统提示词，纯粹是执行前的门控。**模型不知道自己正被问** |
| 生效 | 立即（下一条工具调用） |

| 值 | `write`/`edit` | `bash` | 配置类工具 |
|---|---|---|---|
| 变更前确认 | 确认 | 确认 | 确认 |
| 工作区内自动 | **工作区内 + 可写根清单内免确认**，之外确认 | 确认（可「允许并记住这条命令」，逐字相等） | 确认 |
| 自动编辑 | 全免（含工作区外） | 确认 | 确认 |
| 完全访问 | 全免 | 全免 | 全免 |

细则、可写根清单、三个按钮、以及「bash 为什么每次都问」，见
[permission-modes.md](./permission-modes.md)。

## 三、工作模式（面向谁）

| | |
|---|---|
| 值 | 编码 `code` / 工作 `work` / 设计 `design` |
| 管什么 | 人群定位：提示词附加段、git 界面显隐、设计稿/原型优先 |
| 在哪切 | 会话顶栏那个切换器（「更多」按钮左侧）；**设置 → 通用 → 默认模式**改全局默认 |
| 存哪 | `sessions.app_mode` 列 + kv `pi.app_mode`（全局默认）；从未切过的会话跟随全局 |
| 模型可见 | **是**（`appModePromptBlock`） |
| 生效 | 立即 |

与「会话模式」正交：那个切权限与形态，这个切人群定位。设计档有前置门禁
（ui-design 插件未装/禁用时先引导安装）。

## 四、自动化权限档（无人值守专用）

| | |
|---|---|
| 值 | 只读 / 可写工作区 / 全放开（`read-only` / `workspace-write` / `full`） |
| 管什么 | 定时任务在**没人可问**时，对「需要审批的工具」怎么即时裁决 |
| 在哪切 | 自动化任务的编辑器里（存 `task.toolPolicyProfile`） |
| 模型可见 | 否（只体现在被拒时的理由文案里） |

**⚠️ 与「权限档位」同名，判定口径也已对齐（2026-10 起）**：

- 「工作区内自动」（权限档位）**按路径判**：能判断目标文件在不在工作区/清单里，
  判不了就弹确认。
- 「可写工作区」（自动化档）**同样按路径判**：`write`/`edit` 只在工作区内或本机
  可写根清单内放行，越界即时拒绝；`bash` 与 MCP 拒绝；配置类工具（子代理/技能/
  主题/插件增删）也拒绝。差别只在——没人可问，所以"要问的"变成"直接拒绝"。
- 两档都**不推翻用户显式记过的授权**：`allowCommands` / `allowMcpTools` 是常驻
  授权，判在自动化档位之前（同一个 allow-list 不该在两条路径上语义相反）。

> 历史上这一档是"按工具类别一刀切"（write/edit 一律放行、不看路径），于是档位名
> 承诺的边界并不存在：无人值守的 `workspace-write` 能把文件写到工作区外。
> 需要"写得到处都行"就选 `full`，别再让中间档名不副实。

两者外观还是同一套胶囊（自动化编辑器特意复用了 ModePicker 的形态），所以看名字
几乎必错。默认档也从 `workspace-write` 收紧为 `read-only`（无人值守安全默认）。

## 五、常被误当成「模式」的几样东西

| 名字 | 其实是什么 |
|---|---|
| 计划状态（planning） | `plan` 档的副产物，不是独立旋钮 |
| 思考档位（thinking level） | 模型的推理强度，调参，不是权限也不是形态 |
| 审批级别里的「批准/拒绝」 | 一次性的结果，不是档位 |
| `plan_enter` / `plan_exit` | **模型**申请切档的工具；`plan_exit` 的确认是模式级 HITL |
| 目标模式的轮次上限 | 一条目标的字段，不是模式（见 goal-mode-design.md） |

## 六个入口，各改哪一样

| 入口 | 改的是 |
|---|---|
| 底栏下拉 / Shift+Tab / 「+」菜单的**权限**组 | 权限档位 |
| `/ask` `/plan` `/goal` /「+」菜单的**能力**组 / 能力胶囊 | 会话模式 |
| 顶栏模式切换器 / 设置 → 通用 → 默认模式 | 工作模式 |
| 自动化编辑器里的那个胶囊 | 自动化权限档 |
| `+` 菜单 → 模式（子菜单里两组合起来看） | 权限 + 能力（一次看全） |
