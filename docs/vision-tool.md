# 视觉辅助（see_image）：文本模型主动看图

## 问题

部分模型不支持图片输入（`model.input` 不含 `image`）。既有的多模态降级闭环
会把这类请求里的图片替换成占位文本——会话不报废，但模型确实「看不到」：

- 用户附加的图片被 composer 硬闸挡下（纯文本模型加不了图）；
- `browser_shot` / `screenshot` 的截图结果对模型不可见。

## 方案

做成**工具**而不是自动转述：模型自己决定何时看图、问什么，一次带问题的识别
比盲转述更省也更准，且识别结果作为普通工具结果落转录（刷新、压缩摘要都可见）。

链路（开关打开时）：

1. 请求组装阶段（`resolve.ts streamFn`），纯文本模型的 user/toolResult 里的
   image 块被替换成带 `imageId` 的占位文本：
   `[image attached | source=browser_shot | imageId=img_ab12cd34ef56 | ... call see_image(...) to inspect it.]`
   `imageId = "img_" + sha256(图片base64) 前 12 位`，内容寻址、跨请求稳定。
2. 模型看到占位后调用 `see_image(imageId?, question?)`。
3. 工具按同一哈希在**当前会话消息**里反查原图（不传 ID 取最新一张），
   用视觉模型做一次 one-shot 识别（60s 超时，只收 text_delta）。
4. 文字结果（带 helper/imageId 包装）作为工具结果进入转录；原图不动——
   切回视觉模型后自动恢复可见。

## 开关与提示词零污染（硬约束）

设置 → 模型 → 视觉辅助，事实源 sidecar kv `pi.visionTool`（`{enabled}`），
默认**关闭**。关闭时：

- `buildTools` 不注册 `see_image`（工具表与未引入该能力前逐字节一致）；
- `streamFn` 不做占位替换（请求上下文逐字节一致）；
- 系统提示词不含工具清单，天然不受影响；截图工具描述未改动。

开关翻转经 `set_vision_tool` → `reloadVisionTools()` 重建活动会话工具表
（与记忆开关同机制），即时生效。响应式入口（composer 闸）订阅配置镜像，
设置页翻转后立即重渲染。

## 视觉模型选择

优先级从高到低：

1. **设置页手动指定**（pi.visionTool.provider/modelId）：设置 → 模型 → 视觉辅助
   的下拉（共用 ModelSelector 组件），只列已配凭据、未隐藏、图像输入、非文生图的
   模型；留「自动选择」为缺省。指定项失效（服务删除/取消图像标记）时记日志回落
   下一级，不拖哑工具。
2. **`PI_VISION_MODEL=provider/modelId`**（env 逃生口，无效回落自动）。
3. **自动挑选**：已配凭据（`getAvailable`）、未被 models 行过滤隐藏、声明图像输入、
   非文生图标记；与主模型同 provider 优先，其次输入单价低，id 兜底排序；
   候选清单带 30s TTL 缓存（代理循环里连续调用不重复拉目录）。

**调用失败也走这条链兜底**：目录层面失效与调用层面失败（401 凭据失效、429 限流、
上游下线、网络错误、超时、空回答）都按序回落下一候选，全失败才把最后一次错误
交给主模型。每候选**独立超时**（缺省 60s，`PI_VISION_TIMEOUT_MS` 可调，钳制
[1s, 300s]），慢候选吃满预算不挤占后续候选。用户 Stop 立即终止，不回落、不出
半截答案。

同图同问的应答带进程内 LRU 去重缓存（上限 64 条，键含 helper——换辅助模型自然
失效；中止/失败路径不写缓存），模型循环里重问同一张图不再重复烧视觉调用。

## 子代理

`see_image` 是主会话专属：它的会话事实闭包绑的是主 run（当前模型 + 主对话消息），
子代理拿到只会「看到主对话的图」。子代理定义里声明了也不下发（解析层按未知工具
拒绝；手改 YAML 绕过校验时由 capabilities 解析层兜一道并留诊断）；子代理自己的
截图仍走原占位。

## 异常与降级（失效模式）

原则：**任何一环失败都降级为既有现状（模型看不到图），绝不拖垮聊天主链路。**

| 失败点 | 表现 | 兜底 |
|---|---|---|
| kv 读取失败 / JSON 损坏 | 配置回落默认关 | 功能不存在，聊天正常 |
| kv 写入失败 | 内存即时生效，重启回落 | 日志留痕 |
| set_vision_tool 工具表重建失败 | 逐 run 隔离上报 | execute 面开关二次兜底 |
| 占位替换抛错（纯同步映射，不应发生） | streamFn 捕获回落原 context | 模型看不到图（现状） |
| 会话无图 / imageId 拼错 / 图片被压缩掉 | isError + 可用 ID 列表 | 主模型可转告或省略 ID 取最新 |
| 手动指定的模型失效（目录删/不支持图） | 记日志回落 | env → 自动挑选 |
| helper 调用 401/429/网络/上游下线 | 回落下一候选 | 全失败才报错（带最后错误） |
| helper 超时 | 回落下一候选 | 全超时才报超时 |
| 空回答 / 只吐思考不吐文本 | 回落下一候选 | 全空才报错 |
| 用户 Stop | 立即终止 | 不回落、不出半截答案 |
| 辅助输出超长 | 截断至 4000 字符并标注 | — |
| 开关轮中翻转 | 工具表整组重建 | execute 面开关二次校验 |
| sidecar 重启 | kv 恢复配置，内存缓存重算 | 自愈 |

## 分层关系（多模态降级闭环）

1. **视觉辅助占位**（开关开，`model/image-refs.ts`）：图片 → imageId 占位，
   模型可主动查看；
2. **元数据降级**（pi-ai `downgradeUnsupportedImages`）：占位后无图，no-op；
3. **拒图修复**（`model/image-rejection.ts` + provider-retry）：元数据标错、
   端点真拒图的残余，剥图重试 + sticky。

三层都只改发出去的请求上下文，转录与 UI 不动。

## 已知边界

- 开关打开且有图的会话：占位替换生成新消息对象，cacheWarmer 前缀身份检查
  不命中（该会话期间不暖缓存）；imageId 内容寻址保证占位文本稳定，正式请求
  的前缀缓存不受影响。
- 子代理不接 `see_image`（工具表按 subagent 定义筛选），其截图仍走原占位。
- 压缩摘要（`completeSimple`）不注入占位；但模型调用过 `see_image` 后，
  描述作为工具结果会自然进入摘要。
- 辅助调用不计入主会话 usage 统计（与 AI 审查、标题生成同口径）。
- 移动端只同步提示（无附件硬闸）；开关状态懒加载一次，连续失败 3 次后停止
  重试（旧 sidecar 无此命令时不空打 RPC）。

## 隐私

图片只在模型**主动调用** `see_image` 时发送给所选视觉模型的服务商；工具调用
在 UI 可见。开关默认关闭。
