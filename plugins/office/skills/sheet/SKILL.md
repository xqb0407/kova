# Office · Sheet：表格工作台

表格文档就是工作区里一个**普通的 JSON 文件**（约定名 `<名称>.sheet.univer.json`），
你用现有工具（write / edit / read）直接读写它；用户在右侧「表格」面板（Office 插件，
Univer 引擎）里实时看到渲染结果、可以手动继续编辑（公式栏、右键菜单、多 sheet 页签都可用）。

**文件内容 = Univer 工作簿快照**（本 SKILL 下方有完整格式）。面板打开文件时会自动
补全缺省字段；面板保存时会把用户的手动编辑（含公式计算结果缓存，见下）写回同一文件，
所以**迭代前必须先 read 最新内容**，别基于记忆改。

## 工作流（按此顺序）

1. **创作（分段写盘，别攒成一次大 write）**：面板轮询绑定文件并在落盘后约半秒重渲染，
   让用户**边生成边看到表格长出来**：
   - 第一步先 `write` 一份**骨架**：`name` + `sheetOrder` + `sheets`（含各 sheet 的
     `name`/`rowCount`/`columnCount` + 表头行 cellData），正文先留空。
     路径如 `预算-q3.sheet.univer.json`（根目录或任意子目录均可；面板按
     `*.sheet.univer.json` 认领文件）。
   - **骨架一落盘宿主就自动开板并绑定该文件**——所以骨架必须第一步就写、且是合法
     完整的 JSON，之后的 edit 才会逐次上屏。
   - 然后**一块数据一次 `edit`**（按行段/按区块），每次落盘一次上屏一次。
     ⚠️ 每次落盘的 JSON 必须完整有效（edit 是原地替换；半截括号会让面板报错）。
2. **面板唤起（通常自动，工具是兜底）**：首次 write/edit 该文件时宿主自动开板。
   需要换绑或面板没出来时，显式调 `open_plugin_panel`，参数
   `plugin: "office", panel: "office", path: "预算-q3.sheet.univer.json"`（幂等）。
3. **迭代前必须先 `read`**：面板会把用户的手动编辑防抖写回同一文件（样式表、合并、
   冻结、列宽等都可能被更新）。永远基于最新文件做 edit/write。
   **注意**：面板保存的快照是**全量**格式（含 `appVersion`/`locale`/`styles` 等），
   直接在最新内容上小步 edit 即可，别整档重写成自己的精简版（会丢用户的格式设置）。
4. **样式引用保持稳定**：`styles` 是 id → 样式对象的映射，cell 的 `s` 引用 id。
   改既有样式就改对应 id 的对象；新增样式才加新键。别重排/复用别人的 id。

## 快照格式（工作簿）

```jsonc
{
  "name": "季度预算",          // 工作簿名（首页卡片显示名）
  "sheetOrder": ["s1"],        // sheet 页签顺序
  "styles": {                  // 样式表：id → 样式对象
    "h": { "bl": 1, "cl": { "rgb": "#FFFFFF" }, "bg": { "rgb": "#166534" }, "ht": 2, "vt": 2 },
    "n0": { "n": { "pattern": "#,##0" } }
  },
  "sheets": {
    "s1": {
      "name": "汇总",
      "rowCount": 40,          // 行数（够用即可，别写 100000）
      "columnCount": 10,
      "cellData": {            // 稀疏矩阵：{"行号": {"列号": 单元格}}，行列都从 0 起
        "0": { "0": { "v": "科目", "s": "h" }, "1": { "v": "Q2", "s": "h" }, "2": { "v": "Q3", "s": "h" } },
        "1": { "0": { "v": "营收" }, "1": { "v": 120 }, "2": { "v": 156 } },
        "2": { "0": { "v": "合计" }, "2": { "v": "=SUM(C2:C3)" } }
      },
      "columnData": { "0": { "w": 140 } },   // 列宽（px），可省
      "rowData": { "0": { "h": 28 } },        // 行高（px），可省
      "mergeData": [ { "startRow": 0, "endRow": 0, "startColumn": 0, "endColumn": 0 } ],  // 合并（闭区间），可省
      "freeze": { "xSplit": 0, "ySplit": 1, "startRow": 1, "startColumn": 0 },  // 冻结首行，可省
      "id": "s1"   // ⚠️ 每个 sheet 的 id 必须 = 它在 sheets 里的键，且全文档唯一
                   //    （重复 id → 渲染管线错乱，整表空白；freeze 的 startRow/startColumn
                   //     也必须 ≥ 0，无冻结侧写 0，负值同样导致整表空白）
      // ⚠️ freeze 硬约束：startRow/startColumn 必须 ≥ 0；某一侧不冻结时该侧 split=0
      //    且 start 一律写 0（写 -1 会导致整个表格渲染成空白）
    }
  }
}
```

- 顶层 `id`/`appVersion`/`locale` 可省（面板会补）；从面板回读的档会带全，保留即可。
- 多 sheet：`sheets` 里加多个条目并维护 `sheetOrder` 顺序；跨 sheet 公式用
  `=汇总!C2`（sheet 名引用）。
- **行列号是 0 起**：cellData 的键是数字字符串；`rowCount`/`columnCount` 要 ≥ 用到的
  最大行列 +1。

### 单元格：`v` / `s` / `f`

| 字段 | 说明 |
|---|---|
| `v` | 值：数字直接写数字（`120`）、文本写字符串、布尔写 `true/false`；**别把数字写成字符串**（会被当文本，不能求和） |
| `f` | 公式：`"=SUM(B2:C2)"`、`"=AVERAGE(...)"`、`"=IF(...)"`；以 `=` 开头；与 `v` 并存时面板会重算出真值 |
| `s` | 样式：引用 `styles` 表的 id（推荐），或直接内联样式对象（面板保存时会归一化成 id） |
| `t` | 类型标注极少需要：`4`=强制文本（长编号/手机号防转数字） |

### 样式对象（styles 表的值，全部可选）

| 键 | 含义 | 取值 |
|---|---|---|
| `bl` / `it` / `st` / `ul` | 粗体 / 斜体 / 删除线 / 下划线 | `1` 开（ul/st 可传对象） |
| `fs` | 字号 | 数字（pt），如 14 |
| `ff` | 字体族 | `"Arial"`、`"PingFang SC"` 等 |
| `cl` | 文字色 | `{ "rgb": "#FF0000" }` |
| `bg` | 单元格底色 | `{ "rgb": "#EEF2F7" }` |
| `ht` | 水平对齐 | `1` 左 `2` 中 `3` 右 |
| `vt` | 垂直对齐 | `1` 上 `2` 中 `3` 下 |
| `n` | 数字格式 | `{ "pattern": "#,##0" }`、`"0.00%"`、`"¥#,##0.00"` 等 |
| `bd` | 边框 | 四边 `t/b/l/r`: `{ "s": 1, "cl": { "rgb": "#D4D4D8" } }`（s=线型，1 细线） |
| `tb` | 换行策略 | `1`=溢出 `2`=换行 `3`=截断 |

## 经验值

- **表头一行**：底色 + 白字 + 居中 + 冻结首行；金额列用 `n` 的千分位/百分比 pattern，
  别手工拼 "1,200" 字符串。
- 数字与文本分列：统计列保持 `v` 为数字；代码/编号类用 `"t": 4` 或前缀 `'`。
- `mergeData` 的区间是**闭区间**（start=end 表示合并单格本身，通常不会用到）。
- 行列数别夸张：`rowCount` 按数据量给（数据 30 行就写 40），几万行会让快照巨大。
- 快照里没有的单元格就是空格——别写 `{"v":""}` 填充。

## Excel/CSV 进出（用户在面板点，agent 引导）

- **导入**：面板首页「导入 Excel / CSV」按钮（文件选择器）→ 生成
  `<名>.sheet.univer.json` 并自动开板。xlsx 里的值、公式（含缓存结果）、合并、
  列宽行高、字体/填充/对齐/数字格式/边框都会带进来；图表、数据验证、条件格式
  不转换（导入完成通知里会列有损项）。
- **导出**：表格视图顶栏「xlsx」（值+公式+样式，可在 Excel/WPS 继续编辑）与
  「CSV」（纯值）。
- **话术**：用户给的是 xlsx/csv → 请他点面板首页的导入（二进制你不读）；
  用户要交付 → 改完提醒点「xlsx」。导入完成后你照常 read/edit JSON 快照即可。

## 公式计算值（数据迭代闭环）

面板打开过文档并完成计算后，保存回文件的公式格会带**缓存结果**：
`{ "f": "=SUM(B2:B3)", "v": 40 }` —— 你 read 到 `v` 就是计算结果，可以直接
用来做业务判断（预算是否超了、差多少），据此继续 edit 调整明细，不用自己猜。

- **`v` 不存在或为 null** = 面板还没算过这格（文档从未在面板打开，或刚写完）。
  此时别假设结果；让用户打开面板看一眼（或下次 read）。
- 依赖格改动后结果会更新：面板重算并把新值写回，下次 read 拿到的是新值。

## 典型业务工作流（照这个套路推进）

1. **接手存量**：用户给 xlsx → 引导导入 → read 快照 → 按需求 edit（调数、加公式、
   加汇总行）→ 用户看面板确认 → 提醒导出 xlsx 交付。
2. **从零测算**：骨架 write → 逐块 edit 填数 → 写汇总公式 → 用户开面板（结果缓存
   进文件）→ read 校验计算值是否符合业务约束 → 不符就继续 edit 迭代。
3. **数据 → 汇报**：read 表格快照算关键数（或直接用缓存 v）→ 写
   `<名>.deck.canvas.json` 幻灯片（数字写进文本/图表元素）。

## 放映与导出（向用户说明用）

- 顶栏「xlsx」：值+公式+样式导出（Excel/WPS 可继续编辑）；「CSV」：纯值。
- 表格的持久格式是 `.sheet.univer.json` 本身；xlsx 是交付形态。

```json
    "n0": { "n": { "pattern": "#,##0" } }

  "sheets": {
    "s1": {
      "name": "Sheet1",
      "rowCount": 10,
      "columnCount": 4,
      "cellData": {
        "0": { "0": { "v": "项目", "s": "h" }, "1": { "v": "数量", "s": "h" }, "2": { "v": "单价", "s": "h" }, "3": { "v": "金额", "s": "h" } },
        "1": { "0": { "v": "键盘" }, "1": { "v": 4 }, "2": { "v": 399 }, "3": { "v": "=B2*C2", "s": "n0" } }

    }
  }

```
