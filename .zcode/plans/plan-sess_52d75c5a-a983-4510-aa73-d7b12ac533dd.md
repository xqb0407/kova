# Subagent 消息行 + 右侧 Panel 流式渲染

## 目标效果（对齐截图）

主会话里 `Task` 工具调用渲染成一行紧凑条目：**🤖 子智能体 `Explore` · 描述**，运行中转圈、结束后显示状态与用时；点击在右侧 AgentPanel 打开一个专属 tab，流式渲染该子代理内部全过程（思考、工具行、文本），完成后附最终报告。

## 现状结论（已核实）

- sidecar 子代理已完整实现（`sidecar/pi-agent/src/subagent.ts`）：`SubagentRun` 是进程内第二个 Agent 实例，`handleEvent`（subagent.ts:407）只计数不转发——**内部过程目前不可观测**，这是唯一缺口。
- 协议有"自发通知行"先例：`turn_changed` 无 id、Rust 原样广播（sessions.ts:87），前端 `TauriPiChannel.subscribeTurns`（pi-channel.ts:336）用前缀过滤订阅。子代理活动流走同一条通道，天然支持"父 turn 已结束、后台委派还在跑"。
- 前端工具行体系齐备：`AGENT_TOOL_UI` 注册表 + `ToolRow`（tool-row.aui.tsx:757），`ToolFallback.argSummary` 已认识 `subagent` 字段；panel tab 有 `PanelTabType`/`TAB_META`/`TabContentView` 三处注册点，shell tab 是"tab 只是入口、数据活在模块级 store"的可复用模式。
- `DelegationRecord`（types.ts:61）已有 delegationId/agentName/status/turns/toolCalls/result，但**没有 description、没有活动缓冲**。

## 一、Sidecar：事件转发（subagent.ts / types.ts / protocol.ts）

1. **types.ts**：`DelegationRecord` 增加 `description?: string` 与 `activity: SubagentActivityItem[]`（环形缓冲，上限 ~400 条，满时优先丢 thinking/text 增量、保留结构事件）。新增 item 类型：
   - `{kind:"turn", n}` / `{kind:"thinking"|"text", op:"start|delta|end", id, delta?}` / `{kind:"tool", op:"start|end", toolCallId, toolName, argsSummary?, resultSummary?}` / `{kind:"status", status, turns, toolCalls, report?}`
2. **subagent.ts**：
   - `SubagentRunOptions` 加 `onActivity?(item)`；`handleEvent` 在现有计数之外把 `turn_start`、`message_update`（thinking/text 增量）、`tool_execution_start/end`（参数摘要取 file_path/command/pattern 等首字段，结果取首行）归一化转发。
   - `taskTool.execute`：record 存 `description`；启动时发一条**绑定 chunk** `sendEventChunk(run.threadId, {type:"data-subagentDelegation", data:{toolCallId, delegationId, agentName, description}})`（在活跃 reqId 流内，刷新 attach 可回放）；同时活动 item 以无 id 通知行 `{type:"subagent_activity", delegationId, item}` 广播（`send()` 同款 turn_changed）。
   - `settleDelegation`：追加 `{kind:"status", ..., report}` 并广播。
   - 模块级 `delegationIndex: Map<delegationId, DelegationRecord>`（全局唯一 uuid，供快照查询不必先定位会话）。
3. **protocol.ts**：新命令 `{type:"get_subagent_activity", id, delegationId}` → `{id, type:"subagent_activity_snapshot", record:{agentName,description,status,startedAt,completedAt,turns,toolCalls,report}, items}`（前端打开 tab 时补水合：刷新后、或点开已完成的委派）。头部协议注释同步。

## 二、前端：store 与通道（lib/subagent-runs.ts 新建）

仿 `lib/pi-running.ts` / `lib/shell.ts` 的模块级 store 模式：

- `SubagentRunState { delegationId, agentName, description, status, startedAt, completedAt, items[] }`，按完整 id + 8 位前缀双索引；`toolCallId → delegationId` 绑定表。
- `applyDelegationChunk(data)`：处理绑定 chunk（在 `pi-transport.postTransform` 拦截 `data-subagentDelegation`，仿 data-question 等，pi-transport.ts:249-281）。
- `applyActivityItem(delegationId, item)`：增量合并（delta 追加到同 id 的 thinking/text 项）。
- 通道订阅：`PiChannel` 加可选 `subscribeSubagentActivity?(cb)`；`TauriPiChannel` 实现（listen `pi-chunk-batch` + 前缀 `{"type":"subagent_activity"` 过滤，同 subscribeTurns）；`WsPiChannel` 同步实现（无 id 消息路由）。store 模块初始化时接线一次。
- `useSubagentRun(idOrPrefix)` hook 供视图订阅；快照水合走 `piRequest({type:"get_subagent_activity",...})`。
- 绑定兜底：历史重载（get_history）时绑定 chunk 不在转录里，TaskToolUI 从 result 文本解析 `Delegation ([0-9a-f]{8}) started` 作为 fallback。

## 三、前端：消息行（tool-row.aui.tsx / assistant-message.tsx）

1. 新增 `TaskToolUI: ToolCallMessagePartComponent` 注册进 `AGENT_TOOL_UI.Task`：
   - 视觉复用 `ToolRow`：`label="子智能体"`、icon=BotIcon、`primary=agentName`（mono、链接态）、`secondary=description`；运行状态不取工具 part 的 status（Task 秒回），而是 `useSubagentRun` 订阅：running→spinner+计时，settled→状态徽标+用时。
   - `onOpenPanel` → `openSubagentTab(delegationId, title)`。
   - 展开区（可选简化）：收起最近几条活动作为 preview。
2. **assistant-message.tsx**：`GroupedParts.groupBy` 对 `toolName==="Task"` 返回 `[]`——Task 行不并入"查阅/终端"折叠组，始终独立成行（多个并行 Task 各一行）。

## 四、前端：Panel tab（panel-tabs.ts / tab-registry.tsx / 新建 subagent-tab.tsx）

1. **panel-tabs.ts**：`PanelTabType` 加 `"subagent"`、`PanelTab` 加 `delegationId?: string`、`VALID_TYPES`/`PanelTabExtra` 同步。**不进** `PANEL_TAB_TYPES` 开放列表（用户不能手动 + 开这种 tab，只能从消息行进入）。
2. 打开语义：`openSubagentTab(delegationId)`——已有同 delegationId 的 tab 则 `setActivePanelTab`，否则 `openPanelTab("subagent", {delegationId, title})`（一个委派一个 tab，支持并行多个，不像 focusPanelTab 按类型复用）；并 `dispatchEvent("agent-panel:open")` 展开收起的面板。
3. **tab-registry.tsx**：`TAB_META.subagent`（label 子智能体、BotIcon）+ `TabContentView` 路由。
4. **subagent-tab.tsx**：头部（agent 名 mono + 描述 + 状态/用时/轮次/工具数）；主体按 items 流水渲染——思考行（"思考 · 持续 N 秒"可展开）、工具行（"查看 xxx.ts"等，复用 ToolRow 视觉语言）、文本段（MarkdownText）；自动滚底复用 `ScrollingText`（从 tool-row.aui.tsx 导出）；结束态追加"报告"折叠块（result.report）。tab 挂载时若无 items 先拉快照。

## 五、测试

- sidecar：`subagent.test.ts`（新增）——Task 执行发出 `data-subagentDelegation` + `subagent_activity` 通知；handleEvent 归一化正确；缓冲上限丢增量保结构；`get_subagent_activity` 快照应答（仿 protocol.test.ts 拦 `send`/`sendChunk` 模式）。

## 假设与边界

- 活动缓冲仅存内存（与 delegations 同生命周期，重启/超 50 条清理后丢失，tab 显示"运行记录已过期"）；不新增 JSONL 持久化。
- 子代理 token 级增量经 Rust 20ms 合帧广播，量级可控；不转发 delegate 的 provider 重试细节。
- 远程 WS 通道的通知路由随 `subscribeSubagentActivity` 一并实现，若网关侧有缺口则前端自动降级（能力可选，同 subscribeTurns 契约）。
