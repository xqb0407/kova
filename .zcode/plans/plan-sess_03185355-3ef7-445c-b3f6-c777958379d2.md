# 会话丢失 + 队列消息异常 修复计划

## 诊断结论（日志+数据实证）

数据未丢：d0ebf555 转录完整且 sidecar 中一直活着。丢的是**线程→会话绑定**。

1. **P0 主犯｜绑定劫持**：`piSessionRegistry` 纯内存 Map，Fast Refresh 整页重载 ×3（23:23/23:26/23:36）后清空；`piEnsureThreadSession`（pi-thread-adapter.ts:320）registry 未命中**无条件 new_session**——把恢复线程（threadId 本身=sessionId d0ebf555-…）劫持到新建空会话 f79cd11c。实锤：pi-agent.log `session-rebind: d0ebf555-… -> f79cd11c-…`。「好了吗？」「？」因此落进空会话，AI 无上下文、工作区目录变空目录。
2. **P0 次因｜队列泵丢 sessionId**：sidecar queue_pop 随 popped 返回原始 sessionId（handlers/queue.ts:76），前端泵（prompt-queue-bar.tsx:89-94）丢弃，composer 重发用当前（可能错的）绑定。
3. **P1｜排队消息在用户消息中重复/异常出现**：回填（onReveal）与流式写入竞态，`chat.setMessages(过期数组快照)` 造成重复气泡；web.log `duplicate message id` 刷屏为证。Stop 路径（abortSignal → unregisterQueuedMessage → reveal）同样暴露。
4. **P1｜并入（steer）项 live/历史不一致**：`agent.steer` 注入的是真实 user 消息（必然落转录、历史重建时渲染），直播却刻意不渲染气泡（只显徽标）→ 刷新后"突然出现在用户消息中"。
5. dev Composer hooks 崩溃为 React Compiler 热更特有，不改。

## 修复内容

### P0-1 绑定防劫持 — `pi-thread-adapter.ts`（+ `pi-transport.ts` 复用）
`piEnsureThreadSession` 在 new_session 前加"认领"阶梯：
1. threadId 是合法 UUID 且 `piSessionPrefsMap` 有该会话 → 采纳（`registry.set(threadId, threadId)`）；
2. `piResumableStorage` 里该 chatId 登记过 sessionId → 采纳；
3. `readLastThread()` 指针命中且会话存在 → 采纳；
4. 都没有 → 才 new_session（真·新草稿）。
`pi-transport.ts:198` 发送路径走同一函数。

### P0-2 泵 sessionId 透传 — `prompt-queue-bar.tsx`
弹出队首后若 `popped.sessionId` 与当前绑定不一致或缺失：先把 registry 校正为 popped.sessionId，再 `composer.send()`；绝不走 ensure 新建。

### P1-3 消息数组同步防覆盖 + 去重 — `pi-queue.ts`、`pi-transport.ts`
- reveal/remove 写入时**重读最新数组**（消除 read→write 窗口）；
- reveal 前按 messageId 幂等（已存在不 append），彻底消灭 duplicate id；
- Stop/abort 触发的 reveal 在流式窗口（isRunning / markTurnRunning 未清）时延后到安全点。

### P1-4 steer 项历史一致性 — `prompt-pipeline.ts`、`transcript.ts`
- sidecar：`steerIntoActiveRun` 注入文本加哨兵前缀（仿 `AUTO_CONTINUE_PREFIX` 既有机制，如 `[[queued-steer]] `）；
- transcript：`userUiParts`/`toUiMessage` 识别前缀 → 历史渲染为带「已并入当前回复」标记的用户消息（保留内容、与直播徽标语义一致；不选"历史过滤掉"——那会让刷新后用户看不懂回复在答什么）。

### P1-5 重挂观测
`ResumeRunningThread` switchToThread 成功/失败补 `[resume] switched/failed` 日志；泵恢复路径留痕。

## 验证
1. 单测：认领阶梯四分支；泵 sessionId 透传；reveal 幂等与流式窗口延迟；steer 前缀的转录/历史双向转换。
2. 复现：长任务中 Fast Refresh 重载 ×3 → 发消息必须落原会话、无新会话；排队项派发后气泡只出现一次；Stop 后消息列表不丢不重。
3. steer：并入 → 直播仅徽标；刷新 → 历史显示带「已并入」标记的消息，位置与转录一致。
