## 目标

把无目录会话的产物文件夹 `<task-workspace>/<sessionId>` 从「发出第一条消息的轮初即创建」改为「真正用到才创建」。纯聊天、从未产生文件也从未跑命令的对话，不再在「我的文件」里留下空文件夹。（存量空文件夹按你的选择不处理。）

## 原理

- bash 工具在 Rust 宿主用 `.current_dir(cwd)` spawn（`tool_exec.rs:262/459`），目录不存在会直接失败——这是唯一硬依赖。
- `write` 已有 `create_dir_all(parent)`（`tool_exec.rs:724`）；imagegen、计划文件、文档附件落盘（`docSaveDir`）、记忆文件写入等全部是「写时自带 mkdir」。
- 所以只需把建目录时机挪到 bash 执行前，轮初的无条件创建整段删掉。

## 改动

### 1. `apps/sidecar/pi-agent/src/tools/tools.ts`
- `buildTools(cwd, threadId, getDesignTheme?, getThemeLoads?)` 追加可选参数 `ensureCwd?: () => void`。
- 在 `bash` 那个 `hostTool(...)` 的 envelope 构建闭包里先调 `ensureCwd?.()`（实施时确认 envelope 每次 execute 必被调用；若它只是条件性拼 extra，就把调用挪到该工具 execute 的最前面）。bash 是唯一需要 ensure 的 host 工具，read/write/edit 不自带。

### 2. `apps/sidecar/pi-agent/src/sessions/resolve.ts`
- 三处 `buildTools(...)` 调用点（`resolveSession` 初建、`rebindRunCwd`、`rebindRunThread`）各传入 `() => ensureTaskSessionDir(run)`；闭包运行期读字段，换绑后判断依然正确。`projectContextInfo` 的只读投影不传。
- 删除 `rebindRunCwd` 里的 `ensureTaskSessionDir(run)` 调用（:170）并改写其注释：解绑回落到任务目录时同样不落盘，用到（bash/写文件）时自然建。
- 更新 `ensureTaskSessionDir`（:373-384）与 `taskSessionCwd` 的文档注释：「真正落盘点」从轮初改为 bash 执行前/写文件时；函数本体与幂等、自我设防逻辑不变。

### 3. `apps/sidecar/pi-agent/src/protocol/prompt-pipeline.ts`
- 删除轮初的 `ensureTaskSessionDir(run)` 调用与上方注释（:489-490），移除 import（:45）。
- 更新 `runPromptTurn` 文档注释中「会话准备段（ensureTaskSessionDir / …）」的枚举。

### 4. 测试 `apps/sidecar/pi-agent/test/protocol/protocol.test.ts`
- 「任务工作区目录推迟到轮初落盘」用例改名/改注释为「推迟到用到时落盘」；`ensureTaskSessionDir` 直调断言（幂等、自选目录会话不误建）保留；新增断言：对无凭据环境发 prompt（走 `runTurnBody` 提前返回）后 `run.cwd` 仍不存在。
- 「无目录会话按会话子目录隔离」「delete_session」用例中「真正落盘在轮初」的注释同步改为「工具使用时」。
- 「pre-agent crash still terminates the stream with an error」用例：其抛错注入点（任务目录被同名文件占住 → 轮初 mkdir 抛 ENOTDIR）随轮初调用删除而失效。处理：先找准备段现存的轻量同步抛错点能否重建注入（如键漂移下的 rebind 链）；找不到即删除该用例，并在 `runPromptTurn` 注释中说明隔离层保留为防御（resolveSession 失败的错误结算已有别的用例覆盖）。

### 5. 不改的
- Rust 侧、前端侧零改动：「我的文件」（`app_file_list`）缺目录返回空清单；文件树 `ensureDir` 是纯读、失败按空目录缓存；产物预览/Finder 揭示对缺目录已有报错提示。
- 存量空文件夹不清理。

## 验证

1. sidecar 测试套件：`bun test`（pi-agent 目录），重点是 protocol.test.ts 全绿。
2. 手动冒烟（dev 构建）：
   - 新建对话 → 发一条纯聊天 → `task-workspace` 下无新目录，「我的文件」不出现该会话的空文件夹。
   - 让 agent 写一个文件 → 目录随文件出现。
   - 让 agent 跑一条 bash（如 `pwd`）→ 目录出现且命令成功。
   - 用户自选了工作目录的会话 → 行为不变（不在 task-workspace 建任何东西）。

## 风险与对策

- **模型先 `ls`/read 空工作区**：目录不存在时报 "not-a-directory" 类错误——工具执行在 agent 段，模型可自纠；bash 一跑目录就有了，实际影响极小。
- **后台任务（runInBackground）**：envelope 同样在派发前 ensure，无回归。
- **删会话**：`removeTaskSessionDir` 本来 force 容忍不存在，无需改。
