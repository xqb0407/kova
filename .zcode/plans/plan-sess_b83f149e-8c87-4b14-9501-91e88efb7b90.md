# 修复：pi-ai 请求侧「图片静默降级占位符」

## 根因（已查实）
`pi-ai/dist/api/transform-messages.js` 的 `downgradeUnsupportedImages()` 在 `model.input` 不含 `"image"` 时，把 user 消息里的 image 块静默替换为文本 `"(image omitted: model does not support images)"`。事发时 `custom-qoder/qfmodel` 的生效 input 为 `["text"]`（9-30 备份 DB 实证），1.5MB PNG 因此从未进入请求体。这与 sidecar「一律放行、好过静默吞图」的既定哲学冲突，且元数据默认值就是 `["text"]`（`CUSTOM_MODEL_DEFAULTS`，自定义模型必踩）。

## 实施步骤

1. **扩展 pi-ai 补丁**：`pnpm patch @earendil-works/pi-ai@0.99.2` → 修改 `dist/api/transform-messages.js` 中 `downgradeUnsupportedImages()`：移除 **user 角色**的图片降级分支（user 消息图片一律保留、进请求体；端点不支持时让其报错可见）。`toolResult` 分支保持不动（涉及 provider 兼容，另行决策）→ `pnpm patch-commit` 重新生成 `patches/@earendil-works%2Fpi-ai@0.99.2.patch` → `pnpm install` 应用。

2. **回归测试**：在 `apps/sidecar/pi-agent/test/` 新增 `api/transform-images.test.ts`（bun test）：构造 `model.input=["text"]` + 含图片的 user 消息，断言 `transformMessages` 输出仍保留 image 块（补丁前该断言失败）；同时补一条 toolResult 降级行为不变的断言。

3. **跑测试门**：`pnpm --filter pi-agent-sidecar test`（bun test）+ 桌面端附件相关测试（`apps/desktop/lib/attachments/*.test.ts`、`ThreadController.test.ts`）。

4. **不动的东西**：`pi-vision-warning` toast 保留（元数据转为纯提示用途）；sidecar `preparePromptAttachments` 物理闸门不动；工具结果图片的元数据闸门（openai-completions.js:1086）本阶段不动。

## 验证与风险
- 改完后在应用里把图重发给 qfmodel：模型应能看见图（若仍看不见即网关服务端剥图，与客户端无关）。
- 风险：真正纯文本的端点收到 image_url 可能报 4xx——这是可见错误，符合「好过静默吞图」哲学，且发送前已有 toast 预警。
- 残留缺口（记录不实施）：中转网关服务端剥图无从客户端感知，属端点侧问题。
