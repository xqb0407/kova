# 修复：点"新对话"后刷新页面被拉回旧会话（二次修复）

## 复现与目标
侧边栏点会话 a → 点"新对话" → ⌘R 刷新 → 期望仍停留在新对话；现状回到 a。

## 回切链路（已审）
刷新后回到哪个会话由 `ResumeRunningThread`（app-runtime-provider.tsx）三级决定：
1. 在飞流登记 `piResumableStorage`（sessionStorage+localStorage 双份）；
2. sidecar 运行态水合 `hydrateRunningRegistrations`；
3. `pi-last-thread` 指针（localStorage），无登记时的兜底。

上一版修复只动了第 3 级，且实现是"状态推导"：靠 `WorkspaceThreadSync` 侦测主线程切到无 remoteId 草稿才作废指针。实测无效，说明这条推导没落地——它依赖一串未经运行时验证的假设（草稿项进 `threadItems`、id 匹配、ref 首帧守卫时序、清空与刷新之间无其他写入）。另外指针是在 `await` 网络水合之后才读，与所有 effect 存在天然竞态。

## 改动

### 1. 动作驱动作废（核心）
不再从 runtime 状态推导"用户切到了新对话"，直接在所有"新对话"入口同步清指针：
- `components/agent-thread/clone-thread-shell.tsx`
  - 左栏/抽屉菜单"新对话"项 `handleMenuClick` 的 `isNew` 分支（487/669 处外层 `ThreadListPrimitive.New` 与本组件 onClick 是合成关系，两者都会跑）；
  - 快捷键 `newThread` handler（`switchToNewThread()` 旁，175-185 行）；
  - 搜索弹窗"新对话"项 `onSelect`（778 行旁）。
- `components/assistant-ui/elements/thread-list.aui.tsx`
  - `ThreadListNew` 组件（873 行，任务/项目 tab 里那个）给内层 Button 加 onClick → `clearLastThread()`。

框架内部路径（如删除当前会话后 `ensureNotMain` 自动开新草稿）不经过上述入口，由第 2 条的写通逻辑兜住。

### 2. 指针改为"写通"语义，读值在首帧捕获
- `app-runtime-provider.tsx · WorkspaceThreadSync`：每次主线程判定都同步指针——有 remoteId → record；是未落盘草稿 → clear（上一版加的 `lastKnownRemoteIdRef` 首帧豁免删除，不再需要）。
- `app-runtime-provider.tsx · ResumeRunningThread`：`const [lastThread] = useState(() => readLastThread())` 在**首次渲染**捕获（早于任何 effect），tier-3 用捕获值；本次加载内的清空动作不影响本次决策，下次加载读到的永远是刷新前的真实状态。`switchToThread(target)` 前重读一次指针，若与捕获值不一致（用户加载后又点了新对话）则放弃回切。
- `lib/pi/pi-last-thread.ts`：保留上一版的 `clearLastThread`/工厂与测试（有效）。

### 3. 每加载一条诊断日志（可观测性，验证后保留一行）
`ResumeRunningThread` 决策后 `console.info("[resume] tier=<1|2|3|none> target=<id|null> inFlight=<n> last=<id|null>")`；前端日志管线会落到 web.log。上次是推断出错，这次要留下实证路径。

## 验证（不再只靠静态推断）
1. `bun test lib/pi`（含新增 pi-last-thread 测试）+ `bunx tsc --noEmit`。
2. 启动应用走一遍复现：点 a → 点新对话 → ⌘R，看 web.log 应出现 `tier=none`、界面停在空白新对话。
3. 回归：
   - 停在 a 刷新 → 仍回 a；
   - a 有任务在跑时刷新 → 回 a 并续流（tier-1/2 不受影响）;
   - 新对话发第一条消息后刷新 → 回该新会话；
   - 删除当前会话 → 刷新 → 不回被删会话。
