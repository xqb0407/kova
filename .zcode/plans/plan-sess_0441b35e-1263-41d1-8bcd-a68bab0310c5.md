## 修复：文档（word）内容页空白

### 根因（已从 Univer 1.0.2 源码确认）

Univer 文档模型的合法快照有两条硬性约定，我们都没满足：
- `body.dataStream` 必须以 **`\r\n`** 结尾（`\r`=段落终止符，`\n`=**节分隔符**）
- `body.sectionBreaks` 必须至少一条、指向那个 `\n` 的下标（引擎兼容层会过滤掉不指向 `\n` 的节）

引擎默认空文档体（`getEmptySnapshot`）就是 `{ dataStream: "\r\n", paragraphs: [{startIndex:0}], sectionBreaks: [{startIndex:1}] }`。而面板种子写的是 `{ dataStream: "\r", paragraphs: [{startIndex:0}] }`——没有 `\n`、没有 sectionBreaks，文档没有"节"，排版层**静默渲染空白页**（不抛错）。SKILL.md 教 agent 的格式同样漏了这两点，所以 agent 写的文档也会空白。

### 修复内容

1. **新增 `ui/src/doc/normalize.ts`**（纯函数）：`normalizeDocSnapshot(snapshot)` 载入前容错归一——
   - dataStream 缺 `\n` 收尾则补（最后一段没 `\r` 也顺带补上；空串补成 `"\r\n"`）
   - sectionBreaks 过滤非法项并保证有一条指向末尾 `\n`
   - 段落缺 `paragraphId` 补 `para_<random>`（保唯一）；sectionId 同理可省（引擎自补）
   - 对已合法快照（面板保存回读的）零改动
2. **接入点**：`DocView.applyJson` 载入前过归一器；`OfficeApp.newDocSeed` 与 `doc/univer.ts newDocumentSnapshot` 精简为 `{ id, title }`（引擎用默认空文档体，杜绝手写遗漏）。
3. **`skills/doc/SKILL.md` 更新契约**：dataStream 以 `\r\n` 收尾；**必须带 `sectionBreaks: [{ startIndex: <\n 下标>] }`**；自检规则与示例偏移重算（示例节分隔符下标 = 38）。
4. **新增 `ui/test/doc-normalize.test.ts`**：空种子、缺 `\n`、缺/坏 sectionBreaks、无段落 id、已合法快照零改动 五类用例。
5. **验证**：typecheck + vite build + office 三套 bun test；构建后 office.html 重装生效（拷贝装需在市场页点「安装/更新」）。已按旧格式创建的文档会在载入时被归一器自动修复。

不改动桥/宿主/其他两个引擎。
