## 根因（已证实，非管线 bug）
图片以 image_url 完整发送到模型 API；`custom-qoder/qfmodel` 是文本能力模型（自定义模型默认 `input:["text"]`，sidecar catalog.ts:78），其服务端静默忽略图片 → 模型如实回答"没收到附件"。换视觉模型（如 space-bunny-free）即可正常看图。

## 实施计划：补"模型不支持图片"的提示闸门

1. **sidecar 透传能力字段**：模型列表 RPC 的返回行加 `input`（数据已在 custom-providers.ts:83 / catalog 里，只是没往桌面端传）。
2. **桌面端类型与映射**：`pi-client-base.ts:849` 附近的模型映射加 `supportsImageInput: m.input?.includes("image") ?? false`；对应类型定义（lib/pi/pi-runtime/types.ts）补字段。
3. **发送时提示**：composer 发送含图片附件且当前模型 `supportsImageInput === false` 时，toast 提示「当前模型不支持图片输入，它看不到所发图片——可切换到支持视觉的模型」（发送时判断而非添加时，因为添加后还可能换模型）。落点：apps/desktop/components/agent-thread/ 的发送路径（composer.tsx 或 ThreadController append 前的桌面层）。
4. **sidecar 兜底说明行**：prompt-pipeline 发图前检查 run 的 model.input，不含 "image" 时不传 images 给 agent.prompt（省 token）并追加 noticeLines「[图片未送达：当前模型不支持图像输入]」，让模型不再误称"用户没发图"。
5. **验证**：`~/.bun/bin/bun test lib/`（桌面）+ sidecar 测试 + 双端 tsc；手动回归：qfmodel 发图应见 toast 与说明行，切 space-bunny-free 发图应正常看图。

## 用户侧即时解法（不改代码）
把模型切到支持视觉的（如 space-bunny-free）即可正常发图；或在 设置→模型 里为 qfmodel 勾选图像输入能力（若其真实端点确实支持）。
