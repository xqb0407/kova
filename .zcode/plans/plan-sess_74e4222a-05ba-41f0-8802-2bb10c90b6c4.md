# 内置插件（首方插件随 app 分发）实施方案

## 总体设计

照抄产品内已有先例——**内置主题包**（`design-themes.zip` 经 `with { type: "file" }` 内嵌进 pi-agent 单文件二进制，启动时 `syncBuiltinThemes()` 做版本化"解压/升级/剪旧"）：

1. **载体**：打包脚本从仓库 `plugins/{canvas,ui-design,office}` 生成 `kova-plugins.zip`，构建 sidecar 时生成（不提交仓库，避免 26MB 级文件进 git），bun --compile 内嵌。Rust/Tauri **零改动**；`builtin.ts` 读包入口预留 `PI_BUILTIN_PLUGINS_ZIP` env 覆盖（留改走 Tauri resources 的后门，载体与同步逻辑解耦）。
2. **物化位置**：解包到既有 `cache/builtin/<name>/`（mktId 固定 `"builtin"`，`BUILTIN_MKT_NAME = "内置插件"`）。四条合并链（skills/subagents/commands/mcp/hooks）与 panels 读模型**天然复用，零改动**。
3. **后续更新 = 双通道**（这是用户关心的核心）：
   - **随 app 更新（内置通道）**：sync 比对内置包内容 hash 与 `cache/builtin/.sync.json` 记录的 hash，不一致即重物化 + 剪掉包内已不存在的条目；app 换新安装包 = 内置插件自动升级，无网络依赖。
   - **插件独立热更（市场通道，本计划只留兼容不实现）**：日后官方 git/HTTP 市场发布同名新版本，用户在市场页照常"刷新→更新"，不必等 app 换包；同名遮蔽规则（见下）保证内置条目让位于用户主动安装的市场版本，两通道互不打架。

## Sidecar 改动（apps/sidecar/pi-agent）

### 1. 打包脚本 `scripts/build-builtin-plugins-zip.ts`
- 镜像 `build-design-themes-zip.ts`（含 verify 脚本同族）：输入 `plugins/` 下白名单插件目录（读 `plugins/marketplace.json` 的 plugins 列表），每个插件保留分发文件：`.kova-plugin/plugin.json`、`panels.json`、`icon.svg`、入口 HTML（office.html/canvas.html/design.html）、`skills/`、`.mcp.json`、`mcp/`；剔除 `ui/`、`node_modules/`、`package.json`、`pnpm-lock.yaml`、`verify-*.mjs`、`scripts/`、各类 config。
- 写 `catalog.json`：`{ bundleVersion, plugins: [{name, version}] }`，`bundleVersion` = 各插件目录内容 SHA256 聚合（zip 重打即可见，无需手工版本号）。
- 校验：每插件过 `parsePluginManifest`（清单坏即打包失败）、入口 HTML 存在且不超 `PANEL_ASSET_MAX_BYTES`（32MB）。
- 产物 `src/plugins/bundle/kova-plugins.zip`；接入 `build-sidecar.ts`（compile 前执行，dev/prod 同源）；`package.json` 加 `plugins:pack` / `plugins:verify`；bundle zip 进 gitignore。

### 2. `src/plugins/manifest.ts`
- 增 `BUILTIN_MKT_ID = "builtin"`、`BUILTIN_MKT_NAME = "内置插件"`（与 LOCAL 同族常量）。

### 3. 新模块 `src/plugins/builtin.ts`
- `import bundleUrl from "./bundle/kova-plugins.zip"` + fflate 解析（照 `design-md/catalog.ts`，含测试钩子 `setBuiltinBundleBytesForTest`）。
- `syncBuiltinPlugins()`：
  - 读包入口三态：env `PI_BUILTIN_PLUGINS_ZIP` 覆盖 > 内嵌字节；
  - `cache/builtin/.sync.json` 的 hash == 包 hash → 直接 no-op；
  - 否则逐插件物化到 `cache/builtin/<name>/`（rm 旧 + 解压拷贝，写 `installed.json`：`{pluginId: "<name>@builtin", version, revision: "builtin-<hash8>", installedAt}`），并剪掉不在包内的旧条目；
  - **同名避让**：`scanInstalledSync()` 已有非 builtin 的同名启用条目时跳过该名字（开发机链接装/本地装不受打扰；日后官方市场升级天然走此规则）；
  - 结尾 `invalidateCaches()`；失败非致命 `logErr`（同主题包）。
- `builtinMarketplaceEntry()`：从包 catalog 现场合成市场条目（id `builtin`、`type: "builtin"`、"内置插件"、plugins = 名单 + 已装状态/版本；同 `localMarketplaceEntry` 模式，不落登记表、不参与 add/remove/refresh）。

### 4. 现有模块接线
- `store.ts` `scanInstalledSync`：`mktId === BUILTIN_MKT_ID` 与 isLocal 同处理（市场名固定"内置插件"、不标 `sourceMissing`）。
- `store.ts` `activePlugins()`：内置让位规则——同名存在**非 builtin** 的启用插件时，过滤掉该 builtin 条目（合并链与面板共用这一个出口，遮蔽确定性强于"字典序+diagnostics"兜底）。
- `marketplaces.ts`：`uninstallPlugin` 对 `@builtin` 抛错（"内置插件不可卸载，可禁用"）；`refreshMarketplace` 对 builtin 拒绝（"随应用更新，无需刷新"）。
- `protocol/payloads.ts` `marketplacesPayload()`：marketplaces 数组追加 builtin 条目（与 local 同法，拼进数组防止帧首键错位）。
- `index.ts` 启动闸门：`await initPluginsState()` 之后 `await syncBuiltinPlugins()`（必须早于首批会话读插件组件）。

## 前端改动（apps/desktop）

- `lib/plugins/types`（PiMarketplaceEntry）：`type` 联合加 `"builtin"`。
- `components/marketplace/marketplace-view.tsx`：所有现有 `id !== "local"` 的条件位同步纳入 builtin（隐藏 移除市场/刷新 按钮）；内置条目插件卡片显示"已内置/已启用"徽标 + 启停开关，**不提供卸载按钮**，附"随应用更新"说明文案。
- 设置页 plugins 区（plugins-settings）：`pluginId` 以 `@builtin` 结尾的行隐藏卸载菜单项，保留启停。
- i18n：`marketplace.builtin*` / `settings.pluginsBuiltin*` 中英键（"内置插件""随应用更新""内置插件不可卸载"）。

## 测试（sidecar bun test）

1. `builtin.test.ts`：首启全量物化；hash 相同 no-op；hash 变化重物化 + 剪旧条目；env 覆盖包路径生效；同名避让（先装 `canvas@local` → sync 跳过，uninstall 后下次 sync 恢复）；`activePlugins` 内置让位；启停 kv 跨 resync 保留（pluginId 稳定）；`uninstallPlugin`/`refreshMarketplace` 对 builtin 拒绝。
2. `build-builtin-plugins-zip` 校验：坏清单/缺入口 HTML 拒绝打包；产物 zip 可被 `syncBuiltinPlugins` 消费（verify 脚本对齐 `design:verify`）。
3. 协议测试（仿 subagent-mgmt.test.ts）：`list_marketplaces` 返回含 builtin 条目；`plugins` 载荷含 `canvas@builtin` 等且 `components` 计数正确。
4. 前端：tsc 干净 + next build；市场页内置条目渲染（无卸载/刷新按钮）。

## 交付切分

- **PR-A（后端）**：打包脚本 + builtin.ts + manifest/store/marketplaces/payloads/index 接线 + 单测。合并后 dev 起新 sidecar 即自动获得内置三插件。
- **PR-B（前端）**：市场页/设置页呈现 + i18n。
- **不在本计划**：官方在线市场 CI 发布（市场通道机制已就绪，属发布运营）；Tauri updater（当前 app 无自动更新，内置更新随换包生效）。

## 关键取舍记录

- 载体选内嵌二进制：更新能力与 Tauri resources 无差（都在安装包内），但零 Rust 改动、dev/prod 同源、有主题包先例背书；zip 增量约 5–8MB。
- 同名避让按用户决策"跳过，尊重已有安装"实现，并把它泛化成合并链的"内置让位"规则——同一机制同时兜住开发机链接装与未来官方市场热更两条路。
- 内置插件不可卸载、可禁用；禁用状态与贡献物组件级开关均为既有 kv，重装/升级不受影响。
