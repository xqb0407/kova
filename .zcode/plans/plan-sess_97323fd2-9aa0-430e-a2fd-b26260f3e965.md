# Plan 模式重构：EnterPlanMode/SubmitPlan → plan_enter / plan_write / plan_exit

## 目标设计（按你确认的三个决策）

| 工具 | 参数 | 可用模式 | 行为 |
|---|---|---|---|
| `plan_enter` | 无 | agent | 切到 plan 模式（热换 systemPrompt/工具集），**立即 emit `data-planningState`**（顺带修掉"模型自主进入 plan 但对话框不跟随"的旧缺口），独占批次 |
| `plan_write` | `markdown` 必填、`title` 可选 | plan | 写当前会话计划文件；首次写定路径 `<plans目录>/<sessionId>-<YYYYMMDD-HHmmss>-<标题>.md`，之后每次整体覆盖；**可与其他工具并批**。目录：选了 workspace → `<ws>/.xulux/plans/`，未选 → `~/.xulux/plans/`（全局兜底，复用现有 run.cwd 解析） |
| `plan_exit` | `rationale` | plan | HITL：execute 内经 `pendingToolApprovals` + `data-toolApproval` 挂起等 `tool_confirm`（**无视 approvalLevel**，"完全访问"也要确认，因为是模式级门不是写操作门）。批准 → `applyMode("agent")` + emit → 工具结果指示模型**同一轮直接开始实施**；拒绝 → 留在 plan 模式继续修改。Stop/新 prompt 由现有 `clearPendingToolApprovals` 兜底按拒绝结算。独占批次。未先 `plan_write` 时调用 → 返回错误让其先写 |

- **goal 模式下线**：删 `EnterGoalMode`/`SubmitGoal`、mode-picker 的"目标模式"选项、`SessionMode` 的 `"goal"`；mode-picker 保留 变更前确认/自动编辑/计划模式/完全访问 四项。
- **旧审批卡流整体退役**：`run.proposal`/`PendingProposal`/`planning="awaiting_approval"`/`approve_plan`/`reject_plan` 协议、`closeProposalOnNewPrompt`、`PlanApprovalCard` 组件全删。`PlanningState` 简化为 `inactive | planning`。计划审批 UI 由 `ToolApprovalCard` 对 `plan_exit` 特化渲染承担。

## Sidecar（sidecar/pi-agent/src）

- **types.ts**：`SessionMode="agent"|"plan"`；`PlanningState` 去 `awaiting_approval`；删 `ProposalKind`/`PendingProposal`；`Running` 删 `proposal`，加 `planFilePath?`、`planTitle?`。
- **modes.ts**：头注释重写；`ENTER/SUBMIT_TOOL_NAMES` → `plan_enter/plan_write/plan_exit` 常量；`toolsForMode`（agent = base+subagent+`plan_enter`；plan = `CONTRACT_TOOL_NAMES`+`plan_write`+`plan_exit`）；`modeBeforeToolCall` 门控改名（enter 仅 agent；write/exit 仅 plan；enter/exit 独占、write 不独占）；`savePlanFile` 泛化为"首写定名 + 覆盖写"；新增 `planToolDefs`：`plan_write.execute` 落盘（复用 `sanitizeFileName`/`fileTimestamp`），`plan_exit.execute` 挂起确认 + 批准后 `applyMode("agent")`+`emitPlanningState`；系统提示词（`CONTRACT_MODE_PROMPTS.plan`、`AGENT_MODE_PROMPT`）改写为新三件套流程、删 goal 段；删 `closeProposalOnNewPrompt`；`planningPayload` 去 `proposal`。
- **sessions.ts**：`isEvictable` 删 proposal 判断（保留 planning + pendingToolApprovals），注释更新。
- **protocol.ts**：头注释消息表更新；删 `approve_plan`/`reject_plan` 两个 case（:1227-1255）与 prompt 里 `closeProposalOnNewPrompt` 调用（:403）；`set_mode` 校验只接受 agent|plan；新增 `get_planning_state` 请求 → 返回 `planningPayload`（页面刷新后恢复 UI 模式）。

## 前端（lib + components）

- **lib/pi-session-mode.ts**：类型同步（去 goal / awaiting_approval / proposal / PendingProposal）；删 `approveSessionPlan`/`rejectSessionPlan`；新增 `fetchPlanningState(threadId)` 走 `get_planning_state`。
- **lib/pi-bridge.ts**：响应类型联合同步。
- **components/agent-thread/mode-picker.tsx**：删 goal 选项；`activeKey` 去 goal；挂载/切线程时 `fetchPlanningState` 水合快照（修"刷新后 UI 与 sidecar 模式漂移"）。
- **components/agent-thread/plan-approval-card.tsx**：删文件；**composer.tsx** 删 import 与 `<PlanApprovalCard />` 挂载。
- **components/agent-thread/tool-approval-card.tsx**：`toolName==="plan_exit"` 时特化渲染：标题 + Streamdown 计划 Markdown 预览 + rationale + 批准/拒绝（复用现有 `confirmToolApproval`，审批 chunk 的 input 已透传 `{rationale, title, markdown, filePath}`）。
- **components/assistant-ui/elements/tool-row.aui.tsx**：`AGENT_TOOL_UI` 加 `plan_enter`（"进入计划模式"）、`plan_write`（复用 submitToolUI 样式，"写计划"→ 文件标签）、`plan_exit`（"申请执行计划"，primary=rationale）；**保留旧名 EnterPlanMode/SubmitPlan/SubmitGoal/EnterGoalMode 的渲染条目**，历史转录仍能正常显示。
- **lib/tool-panel.ts**：`SubmitPlan/SubmitGoal` 映射 → `plan_write`（文件标签 focus=toolCallId 渲染 args.markdown）；`hasToolPanel` 同步；**file-view.tsx** 的 `useFilePart` 同理改 key（旧 SubmitPlan 查找保留以兼容历史）。
