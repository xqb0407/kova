# AI 驱动内置浏览器:实施计划

## 目标

让 agent 通过一组 `browser_*` 工具驱动右侧面板的内置浏览器:导航、点击、输入、滚动、读取**渲染后**的页面内容(带 JS 执行结果),用户在面板里实时看到 agent 操作的页面。

## 核心架构决策(已核实可行性)

**把面板的 `<iframe>` 替换为 Tauri 子 webview(unstable 多 webview),控制回路全走 Rust 宿主,不经过前端中转。**

现状根因:`browser-view.tsx:137` 是普通 iframe,跨域页面父窗口无法注入脚本/读 DOM——不换载体就不可能实现"驱动"。

技术栈核实(项目锁定的版本):
- tauri **2.11.5**:开 `unstable` 特性后支持单窗口多 webview(`add_child` 创建子 webview、`set_bounds` 定位、`hide/show`、`navigate`、`eval_with_callback`、`on_page_load`、`navigation_handler`)
- wry 0.55.1:`evaluate_script_with_callback` 将脚本返回值 JSON 序列化回传,macOS(WKWebView)/Windows(WebView2) 均支持(仅 Windows 会吞异常 → 脚本内自行 try/catch)
- 项目已用同款 overlay 模式的社区先例(React 主 UI + 浏览器 overlay 用 set_bounds 定位),且支持 Linux 之外的桌面平台(本项目只发 macOS/Windows)

**数据流**:
```
模型调 browser_click(ref) → sidecar 工具 execute → hostToolCall("browser_click")
  → hostdb host_query(Rust 现有 RPC,含超时/host_cancel 中断) 
  → tool_exec.rs::handle_tool 新分支 → browser.rs 驱动子 webview(eval_with_callback)
  → JS 结果 JSON 回传 → 工具结果返回给模型
```
前端只负责:创建/销毁/定位 webview + 显示 URL/标题;控制回路零前端参与(比走 data-chunk 挂起回路简单一个量级,且天然复用 hostdb 的超时与中断管道)。

## 工具集(sidecar,agent 模式)

| 工具 | 参数 | 行为 |
|---|---|---|
| `browser_navigate` | url | 导航,等 load 完成,返回 {url,title} |
| `browser_snapshot` | — | 提取渲染后的可交互树 |
| `browser_click` | ref | 点击 ref 元素,等稳定后返回新 snapshot |
| `browser_type` | ref, text, submit? | 填输入框(native setter + input 事件,React 兼容),可选回车 |
| `browser_scroll` | direction, amount? | 滚动后返回 snapshot |
| `browser_back` | — | history.back |

**Snapshot 格式**(Playwright 风格,模型读这个来决策):
```
- heading "登录" [h1]
- textbox "用户名" [ref=e3]
- button "提交" [ref=e4]
```
snapshot 脚本给可见元素打 `data-xr-ref` 属性;`browser_click` 按属性定位。页面已变化时返回 "stale ref,请重新 snapshot" 错误,让模型重取——不做选择器重放。上限 400 行/20k 字符截断。

工具描述里写明工作流:navigate → snapshot → 按 ref 操作 → 再 snapshot 确认。

## 里程碑

### M1:Rust 子 webview + 前端换载体(最大风险先行)
1. `src-tauri/Cargo.toml`:tauri 加 `features = ["unstable"]`
2. 新建 `src-tauri/src/browser.rs`:webview 生命周期管理
   - `browser_attach {url}`:创建/显示子 webview(label `browser-panel`,独立 data directory,与用户主会话隔离)
   - `browser_detach`:tab 切换隐藏、tab 关闭销毁
   - `browser_sync_bounds {x,y,w,h}`(物理像素):`set_bounds` 定位到 React 占位 div
   - `on_page_load`/`navigation_handler` → `emit("browser:navigated", {url,title})` 通知前端;弹窗/新窗口统一在当前视图内导航
3. `components/agent-thread/agent-panel/browser-view.tsx` 重写:删 iframe,换成占位 div + ResizeObserver/DPR 换算 → `browser_sync_bounds`;监听 `browser:navigated` 事件维护地址栏/历史栈/`updatePanelTab`;挂载时 `browser_attach`,卸载时 `browser_detach`
4. `lib.rs` 注册命令;`capabilities/default.json` 补命令权限(与现有 kv_* 同模式)
5. **验收**:手动在面板浏览 baidu.com 与 github.com(原 iframe 打不开的 X-Frame-Options 站点现在能用,是本次替换的额外收益);窗口缩放/面板收起展开/多 tab 场景 webview 位置正确

### M2:Rust 自动化原语 + sidecar 工具
1. `browser.rs` 增加自动化入口 `browser_tool(name, params, guard)`(供 `tool_exec.rs::handle_tool` 新分支调用):
   - 全局 Mutex 串行化;另一线程占用时返回明确错误 "browser busy"
   - `eval_with_callback` 执行动作脚本(每个脚本 IIFE + try/catch 返回 `{ok}|{error}` JSON;Windows 吞异常所以必须 catch)
   - navigate 等 load:`on_page_load` 信号 + 30s 兜底超时,SPA 场景退化为固定 settle;`CancelGuard` 在等待循环中检查中断(复用现有 host_cancel)
2. 动作脚本:snapshot(可见性过滤 offsetParent/零矩形/aria-hidden,交互元素打 ref)、click(含 stale ref 检测)、type(native setter + 事件)、scroll、back
3. `sidecar/pi-agent/src/browser-tools.ts`(新文件,仿 `hostTool()` 模式):6 个工具 schema,execute 转发 `hostToolCall(name, cwd, params, signal)`;`tools.ts` 的 `buildTools()` 追加 `...buildBrowserTools(cwd)`
   - 计划模式不加进 `CONTRACT_TOOL_NAMES`(click 会变更外部状态);不加入 `APPROVAL_REQUIRED_TOOLS`(逐击审批会让自主浏览不可用,后续可一行加上)
   - hostdb 侧确认 browser_* 走 60s 工具超时(现有 TOOL_RPC_SLACK_MS 机制)
4. 测试:snapshot 截断/格式化为纯函数抽出,配 `modes.test.ts` 同款测试;Rust 侧测 Mutex 忙判定
5. **验收**:真实走查 —— 打开百度→snapshot→搜"天气"→点结果链接→snapshot;GitHub 登录页表单输入;两个线程并发浏览被拒;浏览中点 Stop 正常中断返回

### M3:面板自动唤起 + 收尾
1. sidecar `browser-tools.ts` execute 时顺带 `sendEventChunk(threadId, {type:"data-panelOpen", data:{type:"browser", url}})`;`lib/pi-transport.ts` tap 里消费(照 data-question 分支旁):`focusPanelTab("browser", {url})` + `dispatchEvent("agent-panel:open")` —— agent 浏览时面板自动展开到浏览器 tab
2. 加载态/错误态 UI(导航失败、busy 提示);`browser-view.tsx` 注释更新(移除"X-Frame-Options 无法嵌入"的旧说明)
3. `protocol.ts` 协议注释补 data-panelOpen 一行

## 风险与对策
- **unstable 特性稳定性**(社区有白屏 issue 报告):M1 先行验证;若某平台子 webview 不可用,`browser-view` 保留 iframe 渲染分支作降级开关
- `eval_with_callback` 线程模型:必要时经 `run_on_main_thread` 派发,实现时验证
- 子 webview 覆盖区域内 React 弹层会被遮挡:浏览器 tab 内容区为专属区域,可接受
- 截图能力(`browser_screenshot`)依赖平台原生 API(WKWebView snapshot / WebView2 CapturePreview),本期不做,列为后续

## 涉及文件
- Rust:`src-tauri/Cargo.toml`、新 `src-tauri/src/browser.rs`、`tool_exec.rs`、`lib.rs`、`capabilities/default.json`
- sidecar:新 `browser-tools.ts`、`tools.ts`、`protocol.ts`(注释)
- 前端:`browser-view.tsx`(重写)、`lib/pi-transport.ts`(+5 行)、`panel-tabs.ts` 不动(复用现有 API)

估算:Rust ~700 行(含 JS 脚本常量)、sidecar ~150 行、前端 ~150 行改动。完成后 iframe 删除,单一渲染引擎,面板浏览器对 agent 完全可编程。
